## 2. 参与者（Actors）

### 2.1 参与者清单

| 参与者 | 类型 | 说明 | 依据 |
|---|---|---|---|
| 读者 | 主要参与者（人） | 系统的借阅主体，注册后持有借阅证；可查询本人借阅信息、预约 / 取消预约、自助缴纳罚款 | `00` §3、`P1` |
| 访客（未注册读者） | 主要参与者（人） | 尚未注册的自然人的临时身份，**仅**用于 `UC-01`；注册成功后即转为「读者」 | `FR-001` |
| 图书管理员 | 主要参与者（人） | 作为**借阅者的代理**在柜台办理借书、还书、登记遗失赔偿；可查询全部借阅记录 | `A2`、`U2`、`P1` |
| 系统管理员 | 主要参与者（人） | 负责系统维护：图书标题、馆藏副本、副本报废、借阅证注销、管理员维护、借阅与罚款规则、减免罚款、调整预约队列 | `A2`、`P1`、`R-10` |
| 系统（定时调度器） | 主要参与者（系统） | 触发时间驱动用例：每日计提超期罚款、预约保留到期扫描与顺延 | `FR-015`、`FR-017`、`R-9` |
| 审计日志 | 次要参与者（系统内部组件） | 接收各写操作的审计记录；不可被修改或删除 | `P2`、`FR-005`、BR-030 |

### 2.2 参与者说明

1. **读者类型不是独立参与者**：`专科生 / 本科生 / 研究生 / 博士生 / 教师` 是**读者**的属性，只决定最大可借数量与借阅期限（`L1`），不构成独立参与者或独立用例分支（`BR-001`、BR-002）。
2. **同一自然人可持多个角色**（如某教师既是读者又协助办理借还）；不引入「馆长 / 审批人」等额外角色（`A2`）。
3. **图书管理员是代理而非自助**：借书 / 还书**必须**由图书管理员在柜台办理（`U2`），读者无自助借还入口；读者在 `UC-09` / `UC-10` 中作为**次要参与者（被代理人）**出现。
4. **系统管理员不可借书**（BR-028）：任何借书请求中操作者角色为系统管理员即拒绝（403）。
5. **不建模的参与者**：支付网关、邮件 / 短信网关、统一身份认证 —— 均在「不做」清单内（`00` §8、`P3`、`R3`）。

### UC-01 注册读者账号

| 项 | 内容 |
|---|---|
| 用例编号 | UC-01 |
| 用例名称 | 注册读者账号 |
| 主要参与者 | 访客（未注册读者） |
| 次要参与者 | 无 |
| 优先级 | P0 |
| 关联需求 | FR-001、FR-003、NFR-004 |
| 关联业务规则 | BR-001、BR-024、BR-029；`TBD-002`、`TBD-010` |

**前置条件**

1. 操作者为未注册的访客，可访问注册入口（注册**不需要**登录）。
2. 系统已初始化读者类型枚举（`专科生 / 本科生 / 研究生 / 博士生 / 教师`）。

**后置条件（成功）**

1. 系统中同时存在读者账号记录与借阅证记录（由 `UC-02` 在同一事务内创建）。
2. 读者可立即使用同一用户名与口令登录（`UC-03`），并按其读者类型适用 `borrowing_rule`。
3. 口令以 BCrypt 持久化，库中无明文。

**后置条件（失败）**：未创建账号、借阅证或任何部分数据；返回明确错误提示。

**基本事件流**

1. 访客提交注册信息：用户名、口令、姓名、系别、读者类型。
2. 系统校验用户名未被占用。
3. 系统校验口令强度：长度 8 位且同时含数字与字母（BR-029）。
4. 系统校验读者类型取值合法（5 种之一）。
5. 系统执行 **`UC-02` 办理借阅证**（`«include»`，自动发证）。
6. 系统在同一事务内持久化读者账号与借阅证（口令以 BCrypt 存储）。
7. 系统返回注册成功结果（含借阅证号）。

**备选事件流**

- A1 读者类型的确定方式：默认由访客**自行选择**系统不审核，后续可由系统管理员修正（`TBD-002` 建议默认）。

**异常事件流**

- E1 用户名已存在 → 拒绝注册，返回明确提示，不创建任何数据。
- E2 口令不满足「8 位且含数字与字母」→ 拒绝注册，返回明确提示，不创建任何数据。
- E3 读者类型取值非法 → 拒绝注册。
- E4 `UC-02` 发证失败（如借阅证号唯一约束冲突）→ 整个注册事务回滚，不留下账号。

### UC-02 办理借阅证（自动发证）★

| 项 | 内容 |
|---|---|
| 用例编号 | UC-02 |
| 用例名称 | 办理借阅证（自动发证） |
| 主要参与者 | 系统（由 `UC-01` 自动触发，**无独立执行者**） |
| 次要参与者 | 访客（注册人）/ 读者（发证对象） |
| 优先级 | P0 |
| 关联需求 | FR-001、FR-003 |
| 关联业务规则 | BR-024、BR-025、BR-027；`TBD-010`、`TBD-011`（不适用，注销见 `UC-16`） |

**建模说明**：依 `R-11`，「办理借阅证」等价于**注册账号时系统自动发证**（`A2` 中「办理借阅证」的管理侧表述在实现上即本用例），**不作为独立触发的用例**，在模型中以 `«include»` 挂接于 `UC-01`。本用例详述是为落实需求方对「办理借阅证」的重点描述要求。

**前置条件**

1. `UC-01` 的第 2~4 步校验全部通过（用户名可用、口令合规、读者类型合法）。
2. 借阅证号生成服务可用。

**后置条件（成功）**

1. 借阅证记录存在，包含**姓名、系别、借阅证号**（BR-027）。
2. 借阅证状态为 `正常`，**无有效期**（BR-025）。
3. 借阅证号非空且全局唯一。
4. 读者账号与借阅证在同一事务内完成持久化；**不存在**「有账号但无借阅证」的记录。

**后置条件（失败）**：`UC-01` 整体回滚，不产生任何账号或借阅证数据。

**基本事件流**

1. 系统按 `UC-01` 提交的姓名与系别构造借阅证主数据。
2. 系统生成**全局唯一**的借阅证号（生成规则见 `TBD-010`，建议 `L` + 年份 + 6 位序列）。
3. 系统将借阅证状态置为 `正常`；借阅证**无有效期字段语义**（BR-025），**不**生成挂失 / 冻结 / 补办相关状态。
4. 系统在同一事务内与读者账号一并持久化（原子操作，BR-024）。
5. 系统向 `UC-01` 返回发证结果（借阅证号）。
6. 注册完成后，读者可立即以同一用户名与口令登录（`UC-03`）并获得借书资格。

**备选事件流**

- A1 借阅证号生成冲突（极小概率）→ 重试生成；仍冲突则转 E1。
- A2 系统管理员后续修正读者类型（`TBD-002`）→ 不改变借阅证号与状态。

**异常事件流**

- E1 借阅证号唯一约束冲突且重试失败 → 事务回滚，`UC-01` 注册失败，返回系统错误。
- E2 存在任何「待审核 / 待发证」的中间状态或查询接口 → **判定违约**（`R-11`：无审核环节）。
- E3 提供管理员手工办证接口或独立办证用例 → **判定违约**（与 `R-11` 冲突）。
- E4 借阅证出现 `挂失 / 冻结` 状态或补办流程 → **判定违约**（`R-12`、`U3`）。

### UC-03 登录与登出

| 项 | 内容 |
|---|---|
| 用例编号 | UC-03 |
| 用例名称 | 登录与登出 |
| 主要参与者 | 读者 / 图书管理员 / 系统管理员 |
| 次要参与者 | 审计日志（仅登录失败时） |
| 优先级 | P0 |
| 关联需求 | FR-003、FR-004、NFR-004 |
| 关联业务规则 | BR-029、BR-030 |

**前置条件**：无（登录入口无需会话）。

**后置条件（成功）**：建立会话，后续受保护操作以该会话作为身份与权限依据。**后置条件（登出 / 失败）**：会话销毁或不存在；登录失败写审计日志。

**基本事件流**

1. 参与者提交用户名与口令。
2. 系统按 BCrypt 比对口令哈希（不使用明文或可逆加密比对）。
3. 校验通过 → 建立会话，记录最后访问时间，返回登录成功与角色信息。
4. 参与者请求登出 → 系统销毁会话。

**备选事件流**

- A1 会话空闲 30 分钟 → 由 `UC-24` 自动失效。

**异常事件流**

- E1 用户名不存在或口令错误 → 返回**统一**失败提示（不区分二者，避免账号枚举），**并写入审计日志**。
- E2 使用已失效会话访问受保护接口 → 401，要求重新登录。
- E3 使用第三方 / 统一身份认证登录入口 → **判定违约**（`P3`、`00` §8）。

### UC-21 每日定时计提超期罚款 ★

| 项 | 内容 |
|---|---|
| 用例编号 | UC-21 |
| 用例名称 | 每日定时计提超期罚款 |
| 主要参与者 | 系统（定时调度器） |
| 次要参与者 | 无（见「假设」：不逐笔写审计日志） |
| 优先级 | P0（核心链路） |
| 关联需求 | FR-017、NFR-009、NFR-005 |
| 关联业务规则 | BR-007 ~ BR-011、BR-013、BR-014、BR-031；`TBD-003`、`TBD-004` |

**前置条件**

1. 定时调度器已启用（Spring `@Scheduled`），且可被测试单独触发（NFR-005）。
2. `fine_rule` 配置表已初始化：借出物类型 × 日费率（中文图书 2 / 外文图书 2.5 / 中文杂志 1 / 外文杂志 1.5 / 论文 3，元/天；宽限期均为 0）。

**后置条件（成功）**

1. 所有「未归还 且 应还日期 < 当前日期」的借阅记录均按**逾期自然日**完成计提，金额 = 逾期天数 × 日费率。
2. 同一自然日对同一条借阅记录**不重复计提**（幂等，NFR-009）。
3. 存在未缴超期罚款的读者被禁止继续借阅；未缴累计额 ≥ 50 元者进入**黑名单**，缴清后解除。
4. 计提结果在 `UC-05` 中可见。

**后置条件（失败）**：不写入部分结果；任务可重跑（幂等）；失败信息留痕。

**基本事件流**

1. 定时调度器触发任务（每日固定时刻执行一次；执行时点与补提口径见 `TBD-004`）。
2. 系统分页查询全部「**未归还** 且 **应还日期 < 当前日期**」的借阅记录。
3. 逐条计算：
   - a. 逾期天数 = 当前日期 − 应还日期（自然日）；**无宽限期**，逾期第 1 天即产生罚款（BR-007）；
   - b. 日费率取该副本所属**图书标题**的**借出物类型**对应费率（BR-031），**读 `fine_rule` 配置表**，**禁止**硬编码或类型分支（BR-014、第七条第 3 款）；
   - c. 应计金额 = 逾期天数 × 日费率。
4. 幂等处理：同一自然日对同一条借阅记录不重复计提；跨天未运行时按逾期自然日总额计算（天然可补提，`TBD-004`）。
5. 系统写入 / 更新 `类型 = 超期`、`未缴` 的罚款记录（BR-032）。
6. 系统按读者汇总**未缴超期罚款累计额**（`TBD-003` 默认口径：当前未缴累计额；赔偿款**不计入**，BR-013）：
   - a. 累计额 > 0 → 该读者在 `UC-09` 前置校验中因「存在未缴罚款」被拒绝（BR-011）；
   - b. 累计额 ≥ 50 元 → 进入**黑名单**，禁止继续借阅，直至缴清（`UC-08` / `UC-19`）后解除（BR-010）。
7. 计提结果可供 `UC-05` 查询展示（在借期间即可见已计提未缴金额）。
8. 任务结束并留执行摘要；失败可安全重跑。

**备选事件流**

- A1 罚款**不区分读者类型**（教师无减免，BR-008）。
- A2 读者在借期间缴清 → 移出黑名单并可继续借阅（`UC-08`）。
- A3 规则变更（`UC-18`）后，下一次计提按新费率生效，无需重启。

**异常事件流**

- E1 `fine_rule` 缺少某借出物类型的费率 → 任务失败并记录；**禁止**按 0 或默认值静默计提。
- E2 单条记录处理失败 → 记录该条并继续；任务标记为部分失败，重跑时幂等补提。
- E3 并发触发（如测试触发与定时触发重叠）→ 幂等，不产生重复罚款。
- E4 采用「归还时一次性结算」而非每日计提 → **判定违约**（`R-9`、第十条第 5 款）。
- E5 将赔偿款计入 50 元封顶 → **判定违约**（BR-013）。

### UC-22 预约保留到期扫描与顺延

| 项 | 内容 |
|---|---|
| 用例编号 | UC-22 |
| 用例名称 | 预约保留到期扫描与顺延 |
| 主要参与者 | 系统（定时调度器） |
| 次要参与者 | 审计日志（系统内部组件） |
| 优先级 | P0 |
| 关联需求 | FR-015、FR-005、NFR-009 |
| 关联业务规则 | BR-017、BR-021；`TBD-005` |

**前置条件**：定时调度器已启用；存在处于 `预约保留` 且保留期已届满的副本（`TBD-005` 默认：与 `UC-21` 共用每日定时任务）。

**后置条件（成功）**：到期未取的预约被取消并顺延给下一位（重新计算 3 天保留期）；无下一位时副本转 `在馆`；每次顺延与取消可追溯；写入审计日志。

**基本事件流**

1. 定时调度器触发扫描。
2. 系统查询全部 `预约保留` 且保留到期时间已过的副本。
3. 逐条处理：
   - a. 队列中仍有下一位预约者 → 取消当前预约，将副本顺延给下一位，**重新计算** 3 天保留期；
   - b. 队列已无下一位 → 副本转为 `在馆`，恢复对外可借。
4. 每次取消与顺延写入审计日志（可通过借阅记录与审计日志追溯）。
5. 任务结束；重复执行幂等（同一预约不重复顺延，同一天不重复重置保留期）。

**异常事件流**

- E1 到期扫描重复执行产生重复顺延或重复重置保留期 → **判定违约**（NFR-009）。
- E2 顺延过程发送任何到馆通知（邮件 / 短信）→ **判定违约**（`R3`）。
- E3 保留期内允许**非队首**读者借出该副本 → **判定违约**（BR-017、`UC-09` E7）。

### UC-23 记录审计日志（`«include»` 子用例）

| 项 | 内容 |
|---|---|
| 用例编号 | UC-23 |
| 用例名称 | 记录审计日志 |
| 主要参与者 | 审计日志（系统内部组件） |
| 次要参与者 | 无 |
| 优先级 | P2 |
| 关联需求 | FR-005、NFR-004 |
| 关联业务规则 | BR-030 |

**前置条件**：某写操作已执行（成功或失败）。

**后置条件**：审计记录落盘，且**不可**被任何业务代码修改或删除。

**基本事件流**

1. 写操作在应用层统一入口收集：操作者标识、操作时间、操作类型、操作对象、操作结果（成功 / 失败）。

**不落审计的操作**：注册与自动发证（`FR-005` 未列举）、只读查询（`UC-04` / `UC-05` / `UC-11`）、定时计提（见第 7 节假设 H-1）。

**异常事件流**

- E1 提供修改或删除审计记录的接口 → **判定违约**（BR-030、NFR-004）。
- E2 业务代码中出现更新 / 删除审计表的调用 → **判定违约**。

| 项 | 内容 |
|---|---|
| 用例编号 | UC-24 |

| 主要参与者 | 系统 |

- A1 30 分钟内有请求 → 重新计时，不强制登出。

- E1 超时阈值硬编码为不可改的常量字面量参与业务判断 → **判定违约**（应为配置项，允许作为默认配置值）。

## 8. 术语与枚举一致性自检

本文件使用的术语与 `01` 基线逐字一致（第二条第 4 款）：

- 读者类型：`专科生 / 本科生 / 研究生 / 博士生 / 教师`
- 借出物类型：`中文图书 / 外文图书 / 中文杂志 / 外文杂志 / 论文`（**图书标题**的属性）
- 副本状态：`在馆 / 已借出 / 预约保留 / 遗失 / 报废`（**无「损坏」**）
- 借阅证状态：`正常 / 已注销`（**无**挂失 / 冻结 / 补办）
- 罚款状态：`未缴 / 已缴`；罚款类型：`超期 / 赔偿`
- 角色：`读者 / 图书管理员 / 系统管理员`

**「不做」清单核对**：本文件**未**出现续借、挂失 / 冻结 / 补办、损坏、催还通知、报表统计、真实支付扣款、人工收银、条码扫描、复杂全文检索、多校区调拨、第三方登录等概念。
