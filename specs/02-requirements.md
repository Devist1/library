## 2. 项目目标

### 2.1 背景

本项目是《软件设计与体系结构》课程实验项目，用于训练需求分析、UML 建模、架构设计、数据库设计、详细设计和代码实现能力（`00` §1）。要求使用 UML 表达分析与设计结果、采用分层架构与 MVC 模式、由 Agent 辅助生成规格/UML/设计与代码，且**所有 Agent 生成内容必须人工审查**，最终交付可运行代码与自动化测试（`00` §7）。

### 2.2 目标

构建一个图书管理系统，支持以下能力（`00` §2、§4，并经 `01` 复审补注）：

1. 注册账号（注册时**系统自动发放借阅证**）
2. 借阅证管理（自动发证、注销）
3. 借阅图书
4. 归还图书
5. 查询借阅信息（读者查本人，图书管理员查全部）
6. 预约图书（含取消预约、保留与顺延、队列调整）
7. 维护图书标题信息
8. 维护馆藏副本（含设置报废）
9. 维护管理员
10. 计算超期罚款（**每日定时计提**）与罚款结清（读者自助缴纳、系统管理员减免）
11. 登记遗失赔偿
12. 维护借阅规则与罚款规则（配置化）
13. 查询图书（书目检索，为借书 / 预约 / 馆藏维护提供定位能力）
14. 审计日志

#### FR-001 注册读者账号并办理借阅证（自动发证）

- **优先级**：P0　**参与者**：读者（访客）
- **描述**：访客提交注册信息（用户名、口令、姓名、系别、读者类型等），系统校验通过后**在同一原子操作内**创建账号并自动生成借阅证（含姓名、系别、借阅证号）。**无审核环节**，不存在「已注册未发证」的中间状态。
- **覆盖说明**：本需求**同时覆盖**需求清单的「**注册读者账号**」与「**办理借阅证**」两项 —— 依 `R-11`，「办理借阅证」等价于**注册时系统自动发证**，不单列为独立用例，故二者合并为同一条需求与同一原子操作。
- **关联业务规则**：BR-024、BR-025、BR-027、BR-029

**验收标准**

1. 注册成功后，系统中同时存在读者账号记录与借阅证记录，借阅证状态为 `正常`，借阅证号非空且全局唯一。
2. 注册与发证为原子操作：系统中不存在「有账号但无借阅证」的记录，也不存在「待审核 / 待发证」状态的查询接口。
3. 口令不满足「长度 8 位且同时含数字与字母」时，注册失败并返回明确的错误提示，且**不创建**任何账号或部分数据。
4. 口令以 BCrypt 持久化：数据库中不存储明文口令，`password_hash` 字段长度按 60 字符设计，其值不等于注册时输入的原文。
5. 注册完成后可立即使用同一用户名与口令登录成功。
6. 读者类型取值为 `专科生 / 本科生 / 研究生 / 博士生 / 教师` 之一，取其他值拒绝注册。
7. 借阅证信息包含**姓名、系别与借阅证号**（BR-027）；借阅证号由系统生成且全局唯一（生成格式见 `TBD-010`），借阅证**无有效期**，初始状态为 `正常`。
8. 注册成功后，该读者可立即按其读者类型适用 `borrowing_rule` 的最大可借数量与借阅期限（BR-001），即具备借书资格。

> 读者类型的**确定方式**（注册时自选 / 管理员指定 / 凭据审核）待确认，见 `TBD-002`。

#### FR-002 注销借阅证（= 需求清单「删除借阅证」）

- **优先级**：P2　**参与者**：系统管理员（依 `A2`「删除借阅证」；是否支持读者自助注销见 `TBD-011`）
- **描述**：将读者 / 借阅证状态由 `正常` 置为 `已注销`，实现逻辑删除并保留历史借阅记录。**覆盖说明**：需求清单的「**删除借阅证**」即本需求（`A2`、`R-12`：删除借阅证等价于读者注销，逻辑删除）。
- **关联业务规则**：BR-025、BR-026、BR-028

**验收标准**

1. 注销后借阅证状态为 `已注销`；该读者在借阅前置校验中被拒绝借书。
2. 注销为**逻辑删除**：读者的历史借阅记录、罚款记录仍可被图书管理员查询到。
3. 注销**不触发**物理删除：读者表与借阅证表的记录仍然存在。
4. 非系统管理员执行注销返回 403。
5. 注销操作写入审计日志。

#### FR-003 登录与登出

- **优先级**：P0　**参与者**：全部角色
- **描述**：以本地用户名 + 口令认证，成功后建立会话；登出即销毁会话。
- **关联业务规则**：BR-029、BR-030

**验收标准**

1. 用户名与口令均正确时登录成功并建立会话。
2. 用户名不存在或口令错误时登录失败，返回**统一的**失败提示（不区分「用户不存在」与「口令错误」，避免账号枚举）。
3. 口令校验基于 BCrypt 比对，不使用明文或可逆加密比对。
4. 登出后当前会话立即失效，使用原会话凭证访问受保护接口被拒绝。
5. 登录失败（含口令错误）写入审计日志。

#### FR-004 会话超时自动登出

- **优先级**：P2　**参与者**：全部角色
- **描述**：无操作超过 30 分钟后会话自动失效。
- **关联业务规则**：BR-029

**验收标准**

1. 最后一次请求后 30 分钟内无任何请求，会话失效；再次访问受保护接口被拒绝并要求重新登录。
2. 30 分钟内有请求则重新计时，不强制登出。
3. 超时阈值 30 分钟为配置项，不在代码中硬编码为不可改的常量字面量参与业务判断（允许作为默认配置值）。

#### FR-005 审计日志

- **优先级**：P2　**参与者**：系统
- **描述**：记录关键操作，保证操作可追溯。
- **关联业务规则**：BR-030

**验收标准**

1. 以下操作**必须**落审计记录：登录失败、借书、还书、预约、取消预约、调整预约队列、登记遗失赔偿、缴纳罚款、减免罚款、维护图书标题 / 馆藏副本、设置副本报废、维护管理员、修改借阅与罚款规则。
2. 每条审计记录至少包含：操作者标识、操作时间、操作类型、操作对象、操作结果（成功 / 失败）。
3. 系统**不提供**任何修改或删除审计记录的接口；业务代码中无更新 / 删除审计表的调用。
4. 审计记录可追溯至 `已注销` 读者与 `报废` 副本的历史操作。

#### FR-006 维护图书标题信息

- **优先级**：P0　**参与者**：系统管理员
- **描述**：新增与删除图书标题；标题携带**借出物类型**属性（中文图书 / 外文图书 / 中文杂志 / 外文杂志 / 论文）。
- **关联业务规则**：BR-031、BR-028、BR-030

**验收标准**

1. 系统管理员可新增图书标题，借出物类型取值为 5 种之一，取其他值拒绝。
2. 同一书籍的中文版与外文版按**两个不同标题**分别录入（`D2`），二者借出物类型分别为「中文图书」与「外文图书」。
3. 删除图书标题时，其历史借阅记录仍可查询（逻辑删除 / 保留可追溯性），具体删除方式见 `TBD-012`。
4. 存在**在借副本**的标题不允许删除，返回明确错误。
5. 图书管理员执行标题维护返回 403（其无任何维护权限）。
6. 维护操作写入审计日志。
7. **添加子项**：新增标题时必填项（书名、借出物类型）缺失被拒绝；同一 ISBN 重复录入同一借出物类型的标题被拒绝（或返回明确提示）。
8. **删除子项**：删除为逻辑删除（`TBD-012`），删除后该标题不再出现在 `FR-023` 查询结果中，也不能再作为新增馆藏副本（`FR-007`）的归属标题；存在**有效预约**的标题不允许删除。

#### FR-007 维护馆藏副本

- **优先级**：P0　**参与者**：系统管理员
- **描述**：在指定图书标题下新增 / 删除馆藏副本，每个副本拥有全局唯一编号，初始状态为 `在馆`。
- **关联业务规则**：BR-019、BR-020、BR-028、BR-030

**验收标准**

1. 新增副本必须归属于一个已存在的图书标题；副本编号全局唯一，重复编号被拒绝。
2. 新增副本的初始状态为 `在馆`。
3. 副本状态只能取 `在馆 / 已借出 / 预约保留 / 遗失 / 报废` 五者之一，**不存在「损坏」状态**；任何接口或数据中出现「损坏」即判定违约。
4. 处于 `已借出` 或 `预约保留` 状态的副本不允许删除。
5. 图书管理员执行副本维护返回 403。
6. 维护操作写入审计日志。
7. **添加子项**：新增副本必须指定所属标题，标题不存在时被拒绝；一次可批量添加多个副本，各副本编号相互不重复。
8. **删除子项**：删除为逻辑删除（`TBD-012`），删除后该副本不可被借出、不可被预约保留，且不出现在 `FR-023` 查询结果中；其历史借阅记录仍可查询。

#### FR-008 设置副本报废

- **优先级**：P1　**参与者**：系统管理员
- **描述**：将副本状态置为 `报废`。该流转**不得由系统自动触发**（包括登记遗失赔偿时）。
- **关联业务规则**：BR-020、BR-021、BR-023、BR-028

**验收标准**

1. 系统管理员可将 `在馆 / 已借出 / 预约保留 / 遗失` 状态的副本置为 `报废`。
2. 置为 `报废` 后，该副本不可被借阅、不可被预约保留。
3. **登记遗失赔偿时副本状态变为 `遗失`，不会自动变为 `报废`**（必须另行执行本需求）。
4. 报废为逻辑删除：该副本的历史借阅记录仍可查询。
5. 非系统管理员执行报废返回 403。
6. 报废操作写入审计日志。

#### FR-009 借阅图书

- **优先级**：P0　**参与者**：图书管理员（作为读者代理）
- **描述**：图书管理员为读者办理借书。系统执行全部前置校验，通过后生成借阅记录并将副本置为 `已借出`。
- **关联业务规则**：BR-001 ~ BR-006、BR-011、BR-021、BR-028

**验收标准**

1. 校验全部通过时借书成功：生成借阅记录（借阅日期、应还日期 = 借阅日期 + 该读者类型的借阅期限），副本状态由 `在馆` 或 `预约保留`（队首读者取书）转为 `已借出`。
2. 任一前置校验失败即拒绝借书，并返回**具体的**失败原因：
   - 存在**超期未还**记录；
   - 存在**未缴罚款**；
   - **在借副本数已达该读者类型上限**；
   - 该读者**已借有同一图书标题的副本**。
3. 在借副本数上限按读者类型生效：专科生 3、本科生 5、研究生 7、博士生 10、教师 15（数值来自 `borrowing_rule` 配置表，非硬编码）。
4. 同一读者对同一图书标题的在借副本数恒 ≤ 1。
5. 仅 `在馆` 状态的副本可被借出；`已借出 / 遗失 / 报废` 状态，以及处于 `预约保留` 且当前读者**非队首预约者**的副本，均不可借。
6. 读者存在**未取预约**时仅作提示，**不阻断**本次借阅。
7. **系统管理员账号发起借书被拒绝**（权限约束），并返回 403。
8. 借阅期限仅由读者类型决定，与借出物类型无关（借出物类型为「论文」与「中文图书」的同一读者，期限相同）。
9. 借书操作写入审计日志。
10. 并发场景下同一副本不会被同时借给两名读者（同一副本的第二次借书请求失败）。

#### FR-010 归还图书

- **优先级**：P0　**参与者**：图书管理员
- **描述**：图书管理员为读者办理还书，系统记录归还时间并按预约情况决定副本去向。
- **关联业务规则**：BR-012、BR-017、BR-021、BR-028

**验收标准**

1. 归还成功：借阅记录标记为已还并记录归还时间；副本由 `已借出` 转为：
   - 该标题存在**有效预约** → `预约保留`，并设置保留到期时间 = 归还时间 + 3 天；
   - 无有效预约 → `在馆`。
2. **归还流程不因存在未缴罚款而被阻断**（罚款缴纳与归还解耦）。
3. 归还不触发「一次性结算罚款」：罚款金额由 `FR-017` 的定时任务计提，归还动作本身不新增罚款记录。
4. 同一条借阅记录重复归还被拒绝。
5. 非 `已借出` 状态的副本不允许归还。
6. 系统管理员执行还书返回 403（依权限矩阵，借还属图书管理员）。
7. 归还操作写入审计日志。

#### FR-011 读者查询本人借阅信息

- **优先级**：P0　**参与者**：读者
- **描述**：读者查询本人的在借记录、历史借阅记录与罚款（含赔偿）记录及缴纳状态。
- **关联业务规则**：BR-012、BR-026、BR-028

**验收标准**

1. 读者只能查询到**本人**的借阅与罚款数据。
2. 查询结果包含：借阅记录（借阅日期、应还日期、归还日期、逾期天数）、图书标题与副本编号、罚款记录（类型、金额、状态 `未缴 / 已缴`）。
3. 读者尝试查询他人数据（如改传入他人读者标识）返回 403，**不返回**他人数据。
4. 在借且已超期的记录可查询到**已计提但未缴**的罚款金额（`FR-017` 计提结果可见）。
5. 列表查询支持分页，禁止一次性加载全部历史记录。

#### FR-012 图书管理员查询全部借阅记录

- **优先级**：P1　**参与者**：图书管理员
- **描述**：图书管理员可查询全部读者的借阅记录，作为柜台代理的支撑能力。
- **关联业务规则**：BR-028、BR-026

**验收标准**

1. 图书管理员可查询任意读者的借阅记录。
2. 读者执行「查询全部借阅记录」返回 403。
3. 支持按读者、图书标题、副本、借阅状态（在借 / 已还 / 超期）条件检索，结果分页。
4. 已注销读者与已报废副本的历史记录仍可查询到。

#### FR-013 预约图书

- **优先级**：P0　**参与者**：读者
- **描述**：读者对当前无在馆副本的图书标题发起预约，进入 FIFO 队列。
- **关联业务规则**：BR-015、BR-016、BR-018、BR-028

**验收标准**

1. **仅当**该标题的全部副本均非 `在馆`（即全部已借出或处于不可借状态）时允许预约；存在任一 `在馆` 副本时预约被拒绝。
2. 同一读者对同一标题不可重复预约（重复预约被拒绝）。
3. 该读者**已借有**同一标题的副本时，不允许预约该标题。
4. 同一读者的有效预约数上限为 3，超出时预约被拒绝。
5. 预约按发起时间 FIFO 入队，队首为该标题队列中最早的预约。
6. 预约**不发送**到馆通知：系统不调用邮件 / 短信等外部通道。
7. 预约操作写入审计日志。
8. 系统管理员能否预约见 `TBD-006`。

#### FR-014 取消预约

- **优先级**：P1　**参与者**：读者
- **描述**：读者主动取消本人的有效预约。
- **关联业务规则**：BR-017、BR-018、BR-028

**验收标准**

1. 读者可取消本人处于「等待中」或「保留中」的预约。
2. 取消后该预约不再参与队列，后续读者依次前移。
3. 若被取消的预约正处于 `预约保留` 保留期，副本按 `FR-015` 顺延给下一位预约者。
4. 取消预约**不产生罚款**、不记违约。
5. 读者不能取消他人的预约（403）。

#### FR-015 预约保留与到期顺延

- **优先级**：P0　**参与者**：系统（定时任务）
- **描述**：副本归还后进入保留期，逾期未取则自动取消并顺延给下一位预约者。
- **关联业务规则**：BR-017、BR-021

**验收标准**

1. 归还时若该标题存在有效预约，副本进入 `预约保留`，保留期内**不可被非队首读者借出**。
2. 保留期为 3 天（自归还时间起算）。
3. 保留期届满仍未取书：该预约被自动取消，副本顺延给队列中下一位预约者，并**重新计算** 3 天保留期。
4. 保留期届满且队列已无下一位预约者：副本转为 `在馆`，恢复对外可借。
5. 保留期内由**队首预约者**取书：副本转为 `已借出`，生成借阅记录，该预约出队。
6. 到期扫描**幂等**：同一预约不会被重复顺延，同一天不会重复重置保留期。
7. 每次顺延与取消均可通过借阅记录与审计日志追溯。

> 保留期到期的扫描执行频率待确认，见 `TBD-005`。

#### FR-016 调整预约队列

- **优先级**：P1　**参与者**：系统管理员
- **描述**：系统管理员可手工调整某标题的预约队列顺序。
- **关联业务规则**：BR-016、BR-028、BR-030

**验收标准**

1. 系统管理员可调整指定图书标题的预约队列顺序。
2. 调整后，下一次保留期到期顺延按**新的**队列顺序执行。
3. 队列调整仅改变顺序，不改变预约记录本身（不产生、不删除预约）。
4. 图书管理员与读者执行队列调整返回 403。
5. 队列调整写入审计日志。

#### FR-017 每日定时计提超期罚款

- **优先级**：P0　**参与者**：系统（定时任务）
- **描述**：每日对「在借且已超期」的借阅记录按日累计罚款，使封顶与黑名单可在借阅过程中触发。
- **关联业务规则**：BR-007 ~ BR-010、BR-014

**验收标准**

1. 对「借阅记录未归还 且 应还日期 < 当前日期」的记录计提罚款，金额 = 逾期天数 × 该副本所属标题的**借出物类型日费率**。
2. 逾期第 1 天即产生罚款（**无宽限期**）。
3. 费率按借出物类型取：中文图书 2、外文图书 2.5、中文杂志 1、外文杂志 1.5、论文 3（元/天）；费率来自 `fine_rule` 配置表，非硬编码分支。
4. 罚款**不区分读者类型**（教师无减免）。
5. 同一自然日对同一条借阅记录**不重复计提**（幂等）。
6. 在借期间（尚未归还）罚款累计即可达到 50 元并触发黑名单，无需等到归还。
7. 计提结果在读者本人查询（`FR-011`）中可见。
8. 定时任务可在应用内由 Spring `@Scheduled` 驱动，且可单独触发以支撑测试。

> 每日执行时点与补提口径待确认，见 `TBD-004`。

#### FR-018 读者自助缴纳罚款

- **优先级**：P0　**参与者**：读者
- **描述**：读者在系统内对本人 `未缴` 的罚款（含超期罚款与赔偿款）发起缴纳，记账式结算，不接入真实支付网关。
- **关联业务规则**：BR-012、BR-013、BR-032、BR-028

**验收标准**

1. 读者可对本人 `未缴` 的罚款发起缴纳，成功后状态置为 `已缴` 并记录结清时间。
2. 缴纳与归还**解耦**：还书之前、之后均可缴纳；归还动作不强制缴费。
3. 缴清后，该读者因「未缴罚款」受到的借阅限制被解除；若因封顶进入黑名单，缴清后移出黑名单。
4. 不接入任何真实支付网关：缴纳不产生外部调用，仅改变罚款状态（符合 `00` §8）。
5. 读者不能代他人缴纳（403）。
6. 已 `已缴` 的罚款不可重复缴纳。
7. 缴纳操作写入审计日志。

#### FR-019 减免罚款

- **优先级**：P1　**参与者**：系统管理员
- **描述**：系统管理员对单笔罚款记录进行减免，减至 0 视为结清。
- **关联业务规则**：BR-012、BR-028、BR-030

**验收标准**

1. 系统管理员可对单笔罚款设置减免金额，减免后剩余金额相应减少。
2. 减免至 0 时，该笔罚款状态置为 `已缴`（视为结清），并解除相应借阅限制。
3. 减免金额不得超过该笔罚款的未缴余额。
4. 读者执行减免返回 403。
5. 减免操作写入审计日志。

#### FR-020 维护借阅规则与罚款规则

- **优先级**：P1　**参与者**：系统管理员
- **描述**：系统管理员在运行时维护借阅规则与罚款规则，无需重新部署。
- **关联业务规则**：BR-001、BR-007、BR-014、BR-028、BR-030

**验收标准**

1. 可维护 `borrowing_rule`：**读者类型** × 最大可借数量 × 借阅期限（5 行）。
2. 可维护 `fine_rule`：**借出物类型** × 日费率（5 行）。
3. 修改后立即对新的借阅与计提计算生效，**无需重启或重新部署**。
4. 规则数值**不在代码中硬编码**：`FR-009` 与 `FR-017` 的计算必须读取配置表；源码中不出现 `3 / 5 / 7 / 10 / 15` 与 `2 / 2.5 / 1 / 1.5 / 3` 等规则字面量参与业务判断（种子数据脚本除外）。
5. 非系统管理员修改规则返回 403。
6. 规则变更写入审计日志。

#### FR-021 登记遗失赔偿

- **优先级**：P1　**参与者**：图书管理员（读者为申报方）
- **描述**：读者申报遗失后，由图书管理员登记赔偿，金额由**登记人人工录入**，系统不做定价计算。
- **关联业务规则**：BR-013、BR-022、BR-021、BR-032、BR-028

**验收标准**

1. 图书管理员可登记遗失赔偿，赔偿金额由登记人**人工录入**，系统不按定价倍数或固定金额自动计算。
2. 登记后，该副本状态由 `已借出` 转为 `遗失`。
3. 登记同时生成一笔 `类型 = 赔偿` 的 `未缴` 款项，可被 `FR-018` 自助缴纳或被 `FR-019` 减免。
4. 赔偿金额**不计入** 50 元封顶：仅赔偿款未缴时，不因「达到 50 元」触发黑名单（见 `TBD-007` 关于是否禁止借阅）。
5. 登记赔偿**不会自动**将副本置为 `报废`（需另行执行 `FR-008`）。
6. 系统**不提供**「遗失 → 在馆」的找回流程（无该接口、无该状态迁移）。
7. 系统管理员执行登记赔偿返回 403（依权限矩阵，借还与柜台业务属图书管理员）。
8. 登记操作写入审计日志。

#### FR-022 维护管理员账号

- **优先级**：P2　**参与者**：系统管理员
- **描述**：系统管理员新增、删除与修改管理员账号（含图书管理员账号与其他系统管理员账号）。
- **关联业务规则**：BR-028、BR-029、BR-030

**验收标准**

1. 系统管理员可新增管理员账号，创建时指定角色（`图书管理员` 或 `系统管理员`）；口令须满足 8 位且含数字与字母，并以 BCrypt 存储。
2. 系统管理员可修改任意管理员账号信息（含自身账号）。
3. **图书管理员修改自己的账号信息被拒绝**（403），该操作由系统管理员执行（`P1`）。
4. 系统管理员可删除管理员账号，但**不允许删除最后一个系统管理员账号**（否则系统失去维护入口）。
5. 删除管理员账号后，其历史操作仍可从审计日志中追溯（审计记录不得被删除）。
6. 非系统管理员执行账号维护返回 403。
7. **系统管理员账号不可借书**（BR-028）：即使该自然人同时持有读者身份，借阅须通过读者账号办理。
8. 账号维护操作写入审计日志。
9. **添加管理员子项**（覆盖需求清单「添加图书管理员」）：新增时须指定角色为 `图书管理员` 或 `系统管理员`；用户名重复被拒绝；口令须满足 8 位且含数字与字母并以 BCrypt 存储；新增成功后该账号可立即登录，并按所指定角色获得权限矩阵（第 3.3 节）对应的操作权限（图书管理员 = 借书 / 还书 / 查询全部借阅记录）。
10. **删除管理员子项**（覆盖需求清单「删除图书管理员」）：删除为逻辑删除，删除后该账号不能再登录，也不能再执行借书 / 还书或任何维护操作；**不允许删除最后一个系统管理员账号**；被删除账号的历史操作仍可从审计日志追溯（审计记录不得被删除）。

> 管理员账号的删除方式（物理 / 逻辑）未由需求方明确；本文件按 NFR-008 采用**逻辑删除**，若改为物理删除须先确认审计可追溯性不受影响。

#### FR-023 查询图书（书目检索）

- **优先级**：P0　**参与者**：读者 / 图书管理员 / 系统管理员
- **描述**：按书名、作者、ISBN 等条件检索图书标题及其馆藏副本，为借书（`FR-009`）、预约（`FR-013`）、馆藏维护（`FR-006` / `FR-007`）提供定位能力。仅提供**最小书目查询**，**不做**复杂全文检索（`00` §8）。
- **覆盖说明**：本需求为本次补入项（原登记为 `TBD-001`），对应需求清单「**查询图书**」；`00` §4 业务清单未列出，但借书 / 预约前必须能定位标题与副本，故提升为正式功能需求。
- **关联业务规则**：BR-019、BR-020、BR-031

**验收标准**

1. 支持按**书名、作者、ISBN** 检索图书标题，匹配方式为精确或前缀匹配；结果**分页**返回（NFR-001）。
2. 查询结果包含标题信息（书名、作者、ISBN、借出物类型）与该标题下**各馆藏副本的编号与状态**（`在馆 / 已借出 / 预约保留 / 遗失 / 报废`）。
3. 支持按**副本状态**过滤（至少支持筛出 `在馆` 副本），用于借书前确认是否存在可借副本。
4. 已逻辑删除的标题（`FR-006`）与副本（`FR-007`）**不出现**在查询结果中。
5. 无有效会话（未登录 / 会话超时）访问查询接口返回 401；已登录的**三种角色均可**查询，读者不因查询他人可借副本而越权（本需求只暴露馆藏状态，不暴露借阅人身份）。
6. 检索条件为空时返回分页默认页，**不加载全表**。
7. **不做**复杂全文检索：不实现分词、相关性排序与跨字段模糊匹配（`00` §8）；违反此条即视为超出范围。
8. 在 `D3` 规模（副本 ≤ 10000）下满足 NFR-001 的响应时间目标 ≤ 2 秒。

> 本需求为只读查询，**不写入审计日志**（审计日志仅覆盖 `FR-005` 列举的写操作与登录失败）。

## 5. 非功能需求

### NFR-001 规模与性能

1. 系统须在 `D3` 声明的数据规模下正常运行：读者 ≤ 5000、副本 ≤ 10000、日均借还 ≈ 300 次、累计流水 ≈ 10 万条。
2. 所有列表查询**必须分页**，禁止一次性加载全表数据。
3. 在上述规模下，单次借书 / 还书 / 预约 / 查询操作的响应时间目标 ≤ 2 秒（单机、H2 文件模式）。**说明**：该阈值需求方未指定，按课程实验常规目标取值，可在 `17-risk-analysis.md` 中调整。

### NFR-002 部署与运行

1. 单机零配置可运行：H2 零配置启动，无需外部数据库服务。
2. 运行 / 演示 / 验收环境使用**文件模式**（`jdbc:h2:file:./data/library`），满足 `D3` 的数据留存要求。
3. 开发 / 测试 / CI 使用**内存模式**（`jdbc:h2:mem:library`），两种模式**不得混用**。
4. 文件模式生成的 `./data/` 目录须加入 `.gitignore`。
5. 以 H2 为**唯一**目标方言，禁止引入 MySQL / PostgreSQL 兼容层。

### NFR-003 架构与可维护性

1. 必须采用四层架构：表现层 / 应用层 / 领域层 / 基础设施层；依赖方向只能自上而下，禁止反向依赖与跨层直连。
2. 必须采用 MVC：Controller 仅负责路由、参数绑定、DTO 转换与 HTTP 状态码。
3. 领域层必须承载全部业务规则；必须引入 Repository（接口在领域层、实现在基础设施层）。
4. 包结构须与 `08-package-diagram.puml` 一致。
5. 必须交付 REST API 契约 `14-api-spec.md`（OpenAPI 形式），实现与契约不一致即视为违约。

### NFR-004 安全

1. 口令哈希算法为 **BCrypt**，`password_hash` 按 60 字符设计；禁止存储明文或可逆加密口令。
2. 口令强度：8 位且含数字与字母。
3. 会话 30 分钟无操作自动登出。
4. 权限校验在应用层统一入口实施；越权访问返回 403 并记入审计日志；禁止依赖前端隐藏元素充当权限控制。
5. 审计记录不可被业务代码修改或删除。
6. 不实现第三方登录与统一身份认证。

### NFR-005 可测试性

1. 测试分三层：领域单元测试、集成测试（Repository 与数据库）、API 接口测试。
2. **必须**使用 H2 内存数据库与种子数据，测试零污染、可重复运行。
3. 核心用例的自动化测试为验收前置条件，至少覆盖：**借书、还书、预约、超期罚款、权限失败**五个场景。
4. 门禁：`15-test-plan.md` 中全部自动化测试通过且核心链路端到端跑通，方可判定交付完成。
5. 定时任务（罚款计提、预约保留到期）必须可被测试单独触发。

### NFR-006 技术栈

1. 后端：Java + Spring Boot。
2. 数据库：H2（唯一）。
3. 前端：Vue 3 + Vite（SPA + JSON API），不采用服务端渲染。
4. 形态：前后端分离的 Web 应用。
5. 新增第三方依赖须说明理由并取得同意，禁止引入与课程范围无关的重型框架。

### NFR-007 交付物与留痕

1. 所有 UML 必须为 PlantUML（`*.puml`）或 Mermaid 文本格式，禁止图片形式 UML。
2. 文档链固定为 `00`~`19`，不得增删编号或另建平行文档。
3. 每次 Agent 生成 specs / UML / 代码 / 测试，必须在 `19-ai-usage-log.md` 登记一条记录。
4. 风险与缺口必须登记 `17-risk-analysis.md`。

### NFR-008 数据留存与可追溯

1. 读者注销、副本报废一律**逻辑删除**：仅改状态字段，保留历史借阅记录。
2. 禁止物理删除读者、借阅证、副本及历史借阅记录。
3. 历史记录须支撑「读者 5000 / 副本 10000 / 累计流水 10 万」规模下的查询。

### NFR-009 可靠性

1. 定时任务（罚款计提、预约保留到期扫描）必须**幂等**：重复执行不产生重复罚款或重复顺延。
2. 借书、还书等关键写操作须在事务边界内，失败时数据保持一致。
3. 同一副本不得被并发借给两名读者。

## 6. 业务规则

### 6.1 借阅规则

| 编号 | 规则 | 依据 |
|---|---|---|
| BR-001 | 最大可借数量与借阅期限**由读者类型决定**：专科生 3 本 / 15 天，本科生 5 本 / 30 天，研究生 7 本 / 30 天，博士生 10 本 / 60 天，教师 15 本 / 60 天 | `L1` |
| BR-002 | **借阅期限与借出物类型无关**，仅由读者类型决定；借出物类型与归还期限无关 | `B2`、`L2`、`R-1` |
| BR-003 | 同一读者对同一**图书标题**的在借副本数恒 ≤ 1（不允许借同一标题的多个副本） | `L2`、`R-18` |
| BR-004 | 借阅前置校验：存在**超期未还**记录、存在**未缴罚款**、**在借副本数达上限**、**已借同标题副本** —— 任一成立即**拒绝借阅** | `L3` |
| BR-005 | 存在**未取预约**时仅作提示，**不阻断**借阅 | `L3` |
| BR-006 | **不支持续借**：如需继续使用，必须先归还再重新借阅 | `L3` |

> 「最大可借数量」的计数口径为**在借副本数**（每借出 1 个副本计 1）；因 `BR-003` 限制同标题 1 副本，其与「在借记录数」在数值上等价（`R-18`）。

### 6.2 罚款规则

| 编号 | 规则 | 依据 |
|---|---|---|
| BR-007 | 罚款费率按**借出物类型**分档（元/天）：中文图书 2、外文图书 2.5、中文杂志 1、外文杂志 1.5、论文 3；**宽限期均为 0** | `F1`、`R-1` |
| BR-008 | 罚款费率**不区分读者类型**（教师无减免） | `F1` |
| BR-009 | 罚款由**每日定时任务**对「在借且已超期」的记录按日累计计提，**不是**归还时一次结算 | `F2`、`R-9` |
| BR-010 | **单读者封顶 50 元**：未缴罚款累计达到 50 元时，禁止继续借阅并进入**黑名单**，直至缴清后解除 | `F2`、`F3` |
| BR-011 | **存在未缴罚款即禁止继续借阅** | `F3`、`L3` |
| BR-012 | 罚款记录含状态 `未缴 / 已缴`；**读者自助缴纳**与**系统管理员减免**（减至 0 视为结清）均可使其结清；**缴纳与归还解耦**，归还不因存在未缴罚款而被阻断 | `R-16`、`R-6`、`R-9` |
| BR-013 | **遗失赔偿金额不计入 50 元封顶**，仅适用于超期罚款 | `R-15` |
| BR-014 | 借阅规则与罚款规则**配置化**：存于数据库配置表，系统管理员运行时可改，禁止硬编码 | `B1`、`R-4` |

> 封顶 50 元的计数口径（未缴累计额 vs 历史累计额）待确认，见 `TBD-003`。

### 6.3 预约规则

| 编号 | 规则 | 依据 |
|---|---|---|
| BR-015 | 预约触发条件：某标题的**全部副本均无 `在馆` 状态**（即全部已借出）时才允许预约 | `R1` |
| BR-016 | 预约队列**严格按预约时间 FIFO**；允许**系统管理员**手工调整队列顺序 | `R2`、`R14` |
| BR-017 | 预约保留：归还且有预约 → 副本置 `预约保留` 并暂停对外借出，**保留 3 天**；逾期未取 → 自动取消并**顺延给下一位**；**不需要到馆通知**（不真实发邮件 / 短信） | `R3` |
| BR-018 | 每位读者的有效预约数量**上限为 3**；读者可**主动取消**预约 | `R3` |

### 6.4 馆藏副本与状态机

| 编号 | 规则 | 依据 |
|---|---|---|
| BR-019 | 领域模型为 **1 个图书标题 → N 个馆藏副本**，每个副本拥有全局唯一编号 | `D1` |
| BR-020 | 副本状态集合为**五态**：`在馆 / 已借出 / 预约保留 / 遗失 / 报废`；**不含「损坏」** | `R-5` |
| BR-021 | 副本状态迁移（**含时间驱动迁移**）如下，必须全部实现 | `R-19`、`R-5`、`R-15` |
| BR-022 | **登记遗失赔偿**由图书管理员执行，金额**人工录入**（系统不计算），副本由 `已借出` 置为 `遗失`；**不自动**触发报废；**不实现**「遗失 → 在馆」找回流程 | `R-15` |
| BR-023 | 副本报废由**系统管理员**执行；报废为逻辑删除，保留历史借阅记录 | `R-5`、`D3` |

**BR-021 状态迁移表**

| 现态 | 事件 | 次态 | 副作用 |
|---|---|---|---|
| `在馆` | 借书 | `已借出` | 生成借阅记录（含应还日期） |
| `在馆` | 系统管理员报废 | `报废` | 写审计日志 |
| `已借出` | 归还（无有效预约） | `在馆` | 记录归还时间 |
| `已借出` | 归还（有有效预约） | `预约保留` | 设置保留到期时间 = 归还时间 + 3 天 |
| `已借出` | 登记遗失赔偿 | `遗失` | 生成 `类型 = 赔偿` 的未缴款项 |
| `预约保留` | 队首预约者取书 | `已借出` | 生成借阅记录，该预约出队 |
| `预约保留` | **保留期届满未取** | `预约保留`（下一位） | 取消当前预约，重新计 3 天保留期 |
| `预约保留` | **保留期届满且无下一位** | `在馆` | 恢复对外可借 |
| `预约保留` | 系统管理员报废 | `报废` | 写审计日志 |
| `遗失` | 系统管理员报废 | `报废` | 写审计日志（**非自动触发**） |
| `报废` | — | （终态） | 不可借、不可预约保留 |
