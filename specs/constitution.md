# Constitution：Agent 行为约束（图书管理系统）

> 本文件是项目的**最高约束层**。`specs/` 下任何文档、UML、代码或测试与本文件冲突时，以本文件为准，冲突内容必须**修正**而非绕过。

- **版本**：v1.0
- **生效日期**：2026-09-21
- **依据**：`00-project-brief.md` 第 7 节（技术要求）、`01-clarifying-questions.md`（A1–E3 人类回答 + `R-1`~`R-19` 复审确认结论，19/19 已关闭）
- **适用对象**：所有 AI Agent（Claude Code / Codex / OpenCode 等）在本仓库内的一切生成与修改行为，以及行使审查职责的人类
- **修订**：本文件自身亦受第五条约束，只能经变更流程修订

**强制性措辞约定**：`必须` / `禁止` = 强制条款，违反即判定该次产出**不予验收**；`应当` = 强推荐，偏离需在 `19-ai-usage-log.md` 中书面说明理由。

## 第一条（适用范围与效力）

1. 本文件约束 Agent 在 `specs/`（文档链 `00`~`19` 与 `*.puml`）及后续 `src/`、测试代码中的**全部生成与修改行为**。
2. Agent **必须**遵守本文件。用户指令与本文件冲突时，Agent **必须首先指出冲突**并等待人类裁决，**禁止**静默执行，也**禁止**以「用户要求」为由绕过本文件。
3. Agent **禁止**自行扩大或缩小交付范围；范围以 `00` 第 4 节业务清单与 `01` 的 `E1` 裁剪结论为准。
4. 本文件不替代 `00` / `01` 的需求内容，只约束**怎么做**；需求内容一律以第二条的基线为准。

## 第二条（唯一事实来源：Single Source of Truth）

1. **需求基线** = `00-project-brief.md` + `01-clarifying-questions.md`（含「复审（Review）」小节）。下游文档**禁止**与本基线冲突。
2. 冲突优先级（自高至低）：**本文件** > `01` 的复审确认结论 > `00` > `02`~`16` 下游文档 > Agent 自身推断与通用经验。
3. Agent **禁止**凭常识补全基线未定义的行为。基线未覆盖且影响实现时，**必须**先登记为待确认项并在 `17-risk-analysis.md` 记录，**禁止**静默假设。
4. 术语与枚举**必须**与基线逐字一致，不得新增、改名或简化：
   - 读者类型：`专科生 / 本科生 / 研究生 / 博士生 / 教师`
   - 借出物类型：`中文图书 / 外文图书 / 中文杂志 / 外文杂志 / 论文`
   - 副本状态：`在馆 / 已借出 / 预约保留 / 遗失 / 报废`（**不含「损坏」**）
   - 罚款状态：`未缴 / 已缴`；罚款类型：`超期 / 赔偿`
   - 借阅证状态：`正常 / 已注销`（**不含**挂失 / 冻结）
5. 凡因复审产生修订的表述，原始措辞**必须划除并注明以确认结论为准**（如 `F1` 的「一天 5 元」），**禁止**让两套口径在文档中并行留存。

## 第三条（UML-as-Spec）

1. **所有 UML 必须是文本化源码**：PlantUML（`*.puml`）或 Mermaid。**禁止**提交截图、导出图片或二进制建模文件（`.png` / `.jpg` / `.vsdx` / `.drawio` 导出物等）作为 UML 交付。
2. UML 是**规格的一部分**，与文字文档具有同等约束力。代码类名、包名、类间关系、调用顺序**必须**与图一致；图与代码不一致时，**以图为规格，修正代码**。
3. UML 清单**固定为 6 张**，编号与文档链对应，**禁止**新增平行文件：

   | 图 | 内容 |
   |---|---|
   | `04-use-case-model.puml` | 用例模型 |
   | `06-domain-class-diagram.puml` | 领域类图（含副本状态枚举） |
   | `08-package-diagram.puml` | 分层包结构 |
   | `10-sequence-borrow-book.puml` | 借书时序 |
   | `11-sequence-return-book.puml` | 还书时序（**不得含缴费步骤**） |
   | `12-sequence-reserve-book.puml` | 预约时序 |

4. 依 `E2`（不需要状态图 / 活动图）与 `R-19` 的折中：**禁止新增 `.puml`**。`06` 只表达状态**枚举**；副本与预约的**时间驱动迁移**以 `05-domain-model.md` 的**文字状态迁移表**（列：`现态 / 事件 / 次态 / 副作用`）表达，且**必须**覆盖：预约保留 3 天到期顺延下一位、读者取书转已借出、登记赔偿转 `遗失`、管理员报废转 `报废`（非自动）。
5. 每张图**必须**能通过 PlantUML 语法解析（可离线渲染）；图内元素命名与第二条的术语表一致。

## 第四条（人工审查：Human-in-the-loop）

1. **所有** Agent 生成内容（specs / UML / 代码 / 测试）在进入下一环节前**必须**经人类审查（依 `00` 第 7 节）。未经审查的产出**禁止**作为下游输入。
2. 审查结论**必须落盘**为可追溯记录，**禁止**只停留在对话中：
   - 每次 Agent 使用在 `19-ai-usage-log.md` 登记一条（依 `E3`），含「人工审查结果」字段；
   - 复审与裁决登记在 `01` 的「复审（Review）」小节，注明是**采纳默认处理**还是**否决并另定**；
   - 交付前按 `18-review-checklist.md` 逐项打勾。
3. Agent **必须**显式区分「AI 默认处理 / 建议」与「人类确认结论」：被否决的默认处理**必须**划除并注明以人类结论为准。
4. Agent **禁止**把自己的推断表述为「用户已确认」。人类未明确表态的内容一律标注为**假设（Assumption）**，并在 `17-risk-analysis.md` 登记。
5. Agent 每次生成或修改 specs / UML / 代码 / 测试后，**必须**在 `19-ai-usage-log.md` 新增一条记录（使用工具、使用阶段、Prompt 摘要、修改文件、输出摘要、测试结果、Git 提交）；「人工审查结果」由人类补齐。

## 第五条（Baseline 冻结与变更控制）

1. 文档一经标记为 **Baseline**（或已在 `19-ai-usage-log.md` 记录提交且被下游引用），即进入**冻结**状态，Agent **不得擅自修改**。
2. **当前冻结基线**：`00-project-brief.md`、`01-clarifying-questions.md`（`R-1`~`R-19` 已 19/19 关闭，待确认 0 项，无阻塞项）。
3. 冻结后若发现上游缺陷，**必须**走变更流程，四步缺一不可：
   1. 提出**变更提案**：说明问题、影响到的下游文档 / 代码、是否破坏已确认结论；
   2. 在 `17-risk-analysis.md` 登记该缺口或风险；
   3. 由**人类裁决**（同意 / 否决 / 折中）；
   4. 裁决后**同步修改全部受影响的下游文档与代码**，并在 `19-ai-usage-log.md` 留痕。
4. 以下均属「擅自修改」，**禁止**：
   - 直接改写冻结文档的既有结论；
   - 绕过提案，在下游文档中采用与基线不同的口径；
   - 以「顺手修正」「统一格式」为由批量重写冻结文档。
5. 后续文档（`02`~`16`）成文并被他处引用后同样冻结，适用同一流程。**禁止**只改一处造成口径分裂。
6. Agent **禁止**在未获人类明确指令时执行 `git commit` / `git push`，**禁止**改写 Git 历史（`push --force`、`reset --hard`、非必要 `--amend`）。

## 第六条（分层架构与 MVC）

1. **必须**采用四层分工：**表现层（Controller）/ 应用层（Service）/ 领域层（Domain）/ 基础设施层（Infrastructure）**。依赖方向只能自上而下（表现层 → 应用层 → 领域层 → 基础设施层接口），**禁止**反向依赖与跨层直连。
2. MVC 的落点**必须**清晰：
   - 表现层：路由、参数绑定、DTO 转换、HTTP 状态码；
   - 应用层：用例编排、事务边界、权限校验入口；
   - 领域层：业务规则与不变量；
   - 基础设施层：Repository 实现、JPA 映射、外部资源。
3. 领域层**必须**承载业务规则（依 `T2`：「不能用经典三层糊弄」）；**必须**引入 Repository 概念 —— 接口定义在领域层、实现位于基础设施层。不要求严格 DDD 聚合。
4. 包结构**必须**与 `08-package-diagram.puml` 一致，**禁止**新增未在图中出现的顶层包。
5. **必须**交付 REST API 契约 `14-api-spec.md`（OpenAPI 形式）；实现与契约不一致即判定为违约。

---

## 第七条（业务规则不得写在 Controller）

1. **禁止**在 Controller（含 DTO / VO）中出现任何业务判断与规则计算，包括但不限于：
   - 借阅前置校验：有超期未还 / 有未缴罚款 / 已达数量上限 / 有未取预约（`L3`）；
   - 可借数量与借阅期限的取值（`L1`）、同标题限借 1 个副本（`L2`）；
   - 罚款费率分档、每日计提、50 元封顶与黑名单判定（`F1` / `F2` / `F3`）；
   - 预约触发条件、FIFO 队列与管理员调整、3 天保留期与顺延（`R1` / `R2` / `R3`）；
   - 副本状态流转判定（`D1` 五态）、遗失赔偿登记（`R-15`）；
   - 角色归属判断（第八条权限矩阵）。
2. 上述规则**必须**位于**领域层**（领域服务 / Policy / 实体方法），Controller 只调用应用层并转换结果。
3. **禁止硬编码规则数值**（依 `R-4`）：借阅与罚款规则**必须**以**数据库配置表**存储、管理员运行时可改：
   - `borrowing_rule`：**读者类型** × 最大可借数量 × 借阅期限（专科生 3/15、本科生 5/30、研究生 7/30、博士生 10/60、教师 15/60）；
   - `fine_rule`：**借出物类型** × 日费率（中文图书 2 / 外文图书 2.5 / 中文杂志 1 / 外文杂志 1.5 / 论文 3，单位元/天；宽限期均为 0）。

   数值**禁止**出现在 Controller、Service 或 SQL 中；**禁止**以 `if (type == 中文图书) return 2;` 之类分支代替查表。
4. **违例判定**：任何一条业务规则若能在 Controller 源码中被定位到（格式校验与 DTO 映射除外），即判定违约，**必须**下沉至领域层并补对应单元测试。

## 第八条（权限控制）

1. 权限矩阵以 `01` 的 `P1`（含 `R-10` / `R-5` / `R-14` / `R-16` 补齐）为**唯一来源**，实现**必须**逐条对应：

   | 事项 | 角色 |
   |---|---|
   | 维护图书标题信息 / 维护馆藏副本 / 设置副本报废 | 系统管理员 |
   | 维护管理员（增删） / 修改管理员账号信息 | 系统管理员 |
   | 修改借阅规则 / 罚款规则 | 系统管理员 |
   | 减免罚款（单笔） / 调整预约队列 | 系统管理员 |
   | 借书 / 还书 / 查询全部借阅记录 | 图书管理员 |
   | 查询本人借阅信息 / 自助缴纳罚款 / 预约 / 取消预约 | 读者 |

2. 硬约束，**禁止**违反：**系统管理员不可借书**；**图书管理员不能修改自己的账号信息**（由系统管理员修改）；图书管理员**无**任何图书 / 标题 / 副本维护权限。
3. 权限校验**必须**在**应用层统一入口**实施。**禁止**只在 Controller 做拦截，**禁止**依赖前端隐藏按钮充当权限控制。越权访问**必须**返回 403 并记入审计日志。
4. 认证与会话（依 `P3` / `R-17` / `R-7`）：本地用户名 + 口令；口令 8 位且含**数字 + 字母**；哈希算法 **BCrypt**（`password_hash` 按 60 字符设计）；会话 **30 分钟**无操作自动登出；不接入第三方登录，**禁止**实现统一身份认证。
5. 审计日志**必须**实现（依 `P2`）：记录操作者、时间、操作内容与结果；审计记录**禁止**被业务代码修改或删除。

## 第九条（核心用例必须有自动化测试）

1. 测试三层**必须**齐全（依 `Q1`）：
   - **领域单元测试**：Policy / Service 的业务规则；
   - **集成测试**：Repository 与数据库交互；
   - **API 接口测试**：Controller 端到端 HTTP 行为。
2. **核心用例的自动化测试是验收前置条件**，**禁止**以「手工验证过」替代。至少覆盖五个场景：**借书、还书、预约、超期罚款、权限失败**。
3. 测试**必须**使用 **H2 内存数据库**（`jdbc:h2:mem:library`）与**种子数据**，保证零污染、可重复运行；运行 / 演示环境使用文件模式（`jdbc:h2:file:./data/library`）。两种模式**禁止**混用（依 `R-8`）。
4. **门禁**：`15-test-plan.md` 中全部自动化测试通过，且核心链路端到端跑通，方可判定交付完成（依 `Q2`）。任何修改后测试不通过，**禁止**提交。
5. **禁止**为了让测试通过而修改测试期望、跳过或禁用用例。如认为断言本身有误，**必须**走第五条变更流程。
6. 实施优先级依 `E1`：**必须**先纵向打通「借书 → 还书」核心链路（含罚款、预约关键分支），再补齐 `00` 第 4 节其余业务。
7. 测试用例命名与断言**必须**使用第二条的术语，**禁止**出现「损坏」「续借」「挂失」等已排除概念。

## 第十条（范围与「不做」清单）

1. 依 `U3` / `E2` / `00` 第 8 节，以下**禁止实现** —— 出现在代码、用例、数据库约束或测试用例中均视为越界：
   - **损坏**状态、挂失 / 冻结 / 补办、续借、催还通知、报表统计；
   - 真实支付扣款与人工收银窗口、图书条码扫描硬件、复杂全文检索、多校区馆藏调拨、第三方 / 统一身份认证；
   - 状态图 / 活动图（`.puml`）。
2. 罚款为**记账式自助结算**：**读者自助缴纳**、**系统管理员可减免**（减至 0 视为结清），**禁止**要求管理员代办收款。缴纳与归还**解耦** —— **禁止**在还书路径中插入缴费步骤，归还不因存在未缴罚款而被阻断；未缴罚款只影响「继续借阅」校验。
3. 遗失赔偿为**人工录入金额**，系统**禁止**实现定价倍数 / 固定金额计算；赔偿款**不计入** 50 元封顶；**禁止**实现「遗失 → 在馆」的找回流程。
4. 数据删除一律**逻辑删除**（只改状态字段，保留历史借阅记录），**禁止**物理删除读者、借阅证与副本。
5. 罚款计提**必须**由定时任务（Spring `@Scheduled`）每日对「在借且已超期」记录累计，**禁止**采用「归还时一次结算」（依 `R-9`）。

## 第十二条（技术栈与运行时约束）

1. 后端：**Java + Spring Boot**；数据库：**H2（唯一）**；形态：**前后端分离的 Web 应用**（依 `T1`）。
2. 前端：**Vue 3 + Vite**，SPA + JSON API，**禁止**采用 Thymeleaf 等服务端渲染（依 `R-13`）。
3. 部署：**单机零配置可运行**。**禁止**引入 MySQL / PostgreSQL 兼容层或双方言适配代码，以 H2 为唯一目标方言。
4. 新增第三方依赖前**必须**说明理由并取得人类同意；**禁止**引入与课程范围无关的重型框架。
5. 文件模式下生成的 `./data/` 目录**必须**加入 `.gitignore`。

## 第十三条（违规处理与冲突裁决）

1. 发现违规或条款冲突时，Agent **必须立即停止**并报告，内容包含：触发条款、违规位置、可选修正方案，然后**等待人类裁决**，**禁止**自行择一执行。
2. 裁决优先级见第二条第 2 款。人类裁决结果**必须**回写到相应文档；被否决的方案**禁止**在下游复现。
3. 人类的裁决记录**必须**同时在 `19-ai-usage-log.md` 与相关文档中留痕，**禁止**只记录在一处。
4. 本条对 Agent 自身生效：Agent **禁止**修改本文件，除非人类明确指示修订。
